# Feature 设计文档

## 设计目标

用一套配置化属性注册表覆盖数值属性、克制、事件特效、条件与状态效果，同时保持旧 `SubAttribute` 数组 API 兼容。装备模块不得直接实现战斗逻辑，只能写入 NBT 并引用属性定义。

## 数据流

```text
属性主清单 -> 分片聚合 -> AttributeRegistry 原子快照
                                 |
物品 Lore / 命名源 -> SXAttributeData(旧数组 + 动态字段)
                                 |
事件上下文 -> 条件公式 -> 白名单 Action -> 伤害/来源/原版效果

锻造 GUI -> 成本事务 -> SX-Item NBT -> 动态 Lore -> 属性解析
来源 API  -> 内存生命周期 -> SQL 事实源 -> Redis 锁与失效广播
```

## 关键决策

| 决策 | 原因 |
|------|------|
| 动态字段与旧数组并存 | 支持热新增属性，同时不破坏外部插件 API。 |
| SQL 为事实源、Redis 只协调 | Redis 丢失不会造成永久数据丢失。 |
| 多服 Redis 故障时拒绝写入 | 避免跨服并发写产生无法判定的最终状态。 |
| NBT 为装备状态唯一真源 | Lore 可重建，不受颜色和第三方重排影响。 |
| 白名单动作而非脚本 | 控制权限边界、线程行为与跨版本风险。 |

## 已知限制

- 根属性配置迁移会保留备份，但 Bukkit 保存主清单时无法保留旧文件注释；旧定义本体通过文件复制保留。
- 自定义附魔注册依赖服务端注册表实现；适配失败时对应附魔被禁用，不创建伪 Lore 附魔。
- JavaScript 属性属于可选扩展子系统：每个文件使用独立引擎，加载或回调失败时仅熔断对应脚本，禁止异常传播到插件核心生命周期与 Bukkit 事件链。
- 自定义事件的同步/异步标记以实际 Bukkit 调用线程为唯一事实源；历史布尔参数仅保留 API 兼容，不参与事件模式判定。
- SQLite 只允许单服务器模式。

## 安全措施

- GUI 操作先全量校验再扣费，异常时按事务快照退款。
- Redis 锁使用随机 token 与 Lua 校验解锁。
- SQL 写入使用事务及版本号乐观锁。
- 属性动作不允许反射类名、执行 JavaScript 或任意文件操作。

## 变更历史

- 保留旧数组与专用属性行为作为兼容影子，避免外部 API 破坏。
