# 属性配置完整说明

属性配置由 `Feature/Attribute/Attributes.yml` 聚合。内置定义放在 `definitions/builtin.yml`，元素、克制、状态等纯配置玩法的示例放在 `definitions/custom.yml`。物品 Lore 中的识别文本由每个属性的 `DiscernName` 或动态字段 `Match` 决定。

## Lore 写法

```text
攻击力: 10-20
暴击几率: 15
生命上限: 50
火元素伤害: 12
```

区间属性可用 `最小值-最大值`；百分比是否显示 `%` 由 Lore 和显示模板决定，数值本身通常直接填写 `15`，不要填写 `0.15`。

## NBT 属性来源

除普通 Lore 外，`Config.yml.NBTAttribute.Nodes` 可配置多个 NBT 路径。节点中的字符串、列表元素和映射叶子会转换为属性文本，并与 Lore 进入同一个属性解析器；例如映射 `攻击力: 10` 等价于同名 Lore 行。

内置装备成长模块把真实属性行写入 `SX-Attribute.Feature.<模块>.Attributes`。显示 Lore 使用 `§X` 行首标记，SX-Item 变量中的显示副本也沿用该标记；解析器会忽略这些显示行，只计算 `.Attributes`，从而避免 Lore 与 NBT 重复读取。

不要把同一个未标记属性列表以多个父子路径重复加入 `Nodes`，否则它仍会按多个独立数据源累计。查看物品实际结构后，应选择最窄且唯一的节点路径。

## 内置战斗属性

| 分类 | 属性文本 | 用途 |
|---|---|---|
| 伤害 | `攻击力`、`PVP攻击力`、`PVE攻击力` | 近战、投射物的基础与额外伤害。 |
| 命中与暴击 | `命中几率`、`暴击几率`、`暴伤增幅`、`破甲几率` | 命中抵消闪避；暴击放大伤害；破甲跳过防御减伤。 |
| 持续攻击效果 | `吸血几率`、`吸血倍率`、`点燃几率`、`雷霆几率`、`撕裂几率` | 命中后回复、点燃、雷击或持续伤害。 |
| 药水攻击 | `致盲几率`、`凋零几率`、`减速几率`、`中毒几率`、`夺食几率` | 按 `AttackPotion.List` 配置施加药水效果。 |
| 防御 | `防御力`、`PVP防御力`、`PVE防御力`、`格挡几率`、`格挡比例`、`反射几率`、`反射比例` | 减伤、格挡和反伤。 |
| 生存 | `生命上限`、`生命恢复`、`闪避几率`、`韧性` | 最大生命、周期回复、闪避和降低触发型效果概率。 |

`格挡几率` 同时被旧 `Dodge` 与 `Block` 识别，若只想保留其中一种机制，请在 `builtin.yml` 中关闭另一项 `Enable` 或改用不同识别文本。

## 移动、采集与原版属性

`builtin.yml` 中带有 `RegistryKey` 的节点会把 SX 属性写入原版 Bukkit 属性；版本不支持时自动跳过。常用属性如下：

| 分类 | 属性文本 |
|---|---|
| 移动 | `移速增幅`、`攻速增幅`、`攻击距离`、`攻击击退`、`横扫比例`、`击退抗性`、`爆炸击退抗性`、`摔落保护`、`摔伤倍率`、`燃烧时长`、`体型增幅`、`跳跃力`、`重力`、`自动上阶`、`潜行速度`、`移动效率`、`水中移动效率`、`飞行速度`、`弹性`、`摩擦修正`、`空气阻力修正` |
| 采集 | `交互距离`、`挖掘效率`、`挖掘速度`、`水下挖掘速度`、`氧气加成` |
| 其它 | `经验增幅`、`幸运`、`视距`、`定位栏发送范围`、`定位栏接收范围`、`名牌距离` |

各节点的 `Version`、`Default`、`Min`、`Max`、`Mode`、`Formula` 和 `CombatPower` 都可配置。不要手动删除未知节点；较新 Minecraft 属性在旧端会安全跳过。

## 动态属性定义

动态定义适合新元素、种族克制、状态和条件化属性。核心字段：

| 字段 | 作用 |
|---|---|
| `Enable` / `Priority` | 独立开关与同事件执行顺序。 |
| `Values.<字段>` | `Match`、`MatchMode`、`Aggregate`、`Min/Max`、`CombatPower`。 |
| `Triggers` | 事件、`When` 条件与 `Actions`。 |
| `Display` | 面板分类、排序与显示行。 |

完整字段、事件、变量与动作清单见 [统一属性引擎](features/attribute.md)。`custom.yml` 自带火元素伤害/抗性、亡灵克制、中毒 Debuff 和低血量 Buff 示例，复制节点并修改 ID 即可扩展。

## 条件与物品可用性

`Config.yml.Condition` 识别以下 Lore 条件：主副手/护甲类型、限制等级、限制职业、耐久度、出售价格和到期时间。条件不满足时，该物品的属性不会进入实体最终属性。

属性分片修改后使用 `/sxa reload`。若重载失败，旧注册表继续生效，检查控制台的重复 ID、公式或 YAML 错误后再重试。
