# 高版本原版属性扩展清单（决策文档）

> 用途：列举可接入 SX-Attribute 的原版属性，供圈选最终实现范围。
> 数据来源：[Minecraft Wiki - Attribute](https://minecraft.wiki/w/Attribute)（截至 2026-07，覆盖至 26.2 快照）。
> 现有已包装：`movement_speed`(移速)、`attack_speed`(攻速)、`max_health`(生命)、`attack_damage`(攻击力)。

---

## 一、接入机制说明（先读）

每个新属性 = 一个新的 `SubAttribute` 子类，放进 `data/attribute/sub/update` 包，
完全照搬 `AttackSpeed.java` 的结构。核心只有两点差异：

### 1. 名称解析走现有 `AttributeUtil`

```java
// 优先按 registry key(新版), 回退按枚举名(旧版), 跨 1.20.5 ~ 26.x 安全
AttributeInstance instance = AttributeUtil.getInstance(player, "<registry_key>", "<旧枚举名>");
if (instance != null) {
    instance.setBaseValue(默认值 * (100 + values[0]) / 100);  // 百分比增幅模式
}
```

- 新版名 = 表中"registry key"列（如 `scale`）
- 旧枚举名 = 表中"旧枚举名"列（如 `GENERIC_SCALE`；玩家专属属性为 `PLAYER_` 前缀）
- 属性不存在时 `getInstance` 返回 `null` 且已判空 → **漏门控也只是静默不生效，不会崩**，降级安全。

### 2. 版本门控用 `isVersionAtLeast(minMinor)`

```java
if (SXAttribute.isVersionAtLeast(21)) {   // ≥ 1.21
    new Scale().registerAttribute();
}
```

> ⚠️ **版本识别精度限制**：`versionSplit` 仅存 `[major, minor, patch]` 三段，
> **无法区分补丁号**（如 1.20.1 vs 1.20.5）。因此：
> - 1.20.5 引入的属性，门控统一挂在 `isVersionAtLeast(21)`（即 ≥1.21）最保险；
> - 1.21.6 / 26.2 引入的属性，靠 `AttributeUtil` 的 `null` 降级兜底即可（低版本自动静默）。
> - 若需精确到补丁号，需额外扩展 `versionSplit` 解析与判断方法（见文末「版本识别增强建议」）。

## 二、值增幅模式约定

沿用现有攻速/移速的"百分比增幅"惯例：面板配置数字 = 增幅百分比，
`最终值 = 原版默认值 × (100 + 增幅) / 100`。
但部分属性更适合"绝对值叠加"（如护盾值、攻击距离），实现时按玩法选择模式，下表已标注建议模式。

## 六、不建议做（生物专属 / 玩家无效）

以下属性仅对特定生物有意义，玩家身上无效果或无意义，**不纳入考虑**：

- `follow_range`（mob 追踪范围）
- `tempt_range`（mob 被诱惑范围）
- `spawn_reinforcements`（僵尸召唤援军）
- `nameplate_score_distance` / `below_name_distance`（记分板显示距离）

## 七、版本识别增强建议（可选）

当前 `isVersionAtLeast(minMinor)` 只比较**次版本号**，无法精确到补丁号。
若圈选了大量按补丁号引入的属性（1.20.5、1.21.6、26.2），建议增强：

**方案 A（推荐，零风险）**：不改版本判断，全靠 `AttributeUtil.getInstance` 返回 `null` 自动降级。
低版本注册了也不生效、不报错，只是面板显示 `N/A` 需在 Message.yml 中不配置对应行即可。

**方案 B（精确门控）**：新增补丁号感知的判断方法：
```java
// 比较到补丁号: isVersionAtLeast(1, 20, 5) 表示 ≥ 1.20.5
public static boolean isVersionAtLeast(int major, int minor, int patch) {
    if (versionSplit[0] != major) return versionSplit[0] > major;
    if (versionSplit[1] != minor) return versionSplit[1] > minor;
    return versionSplit[2] >= patch;
}
```
> 注意：新版本号方案（26.x）主版本 > 1，此方法对 `major=1` 的判断会直接返回 true，符合"新版覆盖旧特性"预期。

## 八、实现工作量估算

每接入 1 个属性需改动：
1. 新建 `sub/update/Xxx.java`（约 50~70 行，仿 `AttackSpeed`）
2. `SXAttribute.java` 注册区加 1 行（含版本门控）
3. `Message.yml` 面板 `BASE_LORE`（或对应分区）加 1 行显示

| 范围 | 属性数 | 预估新增文件 | 预估改动行数 |
|---|---|---|---|
| 仅 Tier 1 | 6 | 6 | ~450 |
| Tier 1+2 | 22 | 22 | ~1500 |
| 全部 T1+T2+T3 | 30 | 30 | ~2100 |
